# Statement

Generated harnesses tend to include state/memory scaffolding in form but not in function: State classes are defined, but state-saving interfaces, periodic checkpointing, and actual checkpoint usage are nearly absent, and the dead code in generated harnesses concentrates in exactly these unexercised components.

# Evidence

- 11 of 18 Code artifacts define a State class, but only one exposes a state-saving interface and only one implements periodic checkpointing; no checkpoint event appears in 26,679 recorded task trajectories. [^primary]
- Of 108 Code component instances, 18 were never observed in real runs — all concerning state/memory; separately, 124 of 587 Writing features were confirmed dead code. [^primary]
- Evolution rarely touches the gap: of 64 official version switches, only 4 modified state, while 58 changed execution/control flow. [^primary]

# Caveats

- Observational finding from one benchmark's artifacts; other generation regimes (different seeds, prompts, or domains) may differ. [^primary]
- Absence of checkpoint events does not prove checkpointing is impossible for these models, only that it was not produced under these conditions. [^primary]
